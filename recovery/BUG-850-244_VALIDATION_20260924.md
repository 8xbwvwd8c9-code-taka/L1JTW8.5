## Problem

The character gift claim path published the claimed byte in live RAM before proving that `character_gift.data` had been durably updated. The SQL helper swallowed `SQLException`, while the caller continued to grant the configured reward.

That allowed a database failure to leave the live claim marked while durable state remained unclaimed, and still deliver the reward.

Required contract:

```text
gift claim must persist exactly once before RAM claimed-state publication and reward delivery
DB/CAS failure -> RAM unchanged and no reward
```

## Repair

The validated work repair changes both authoritative recovered source forms:

- `recovered-src-obf/ao/k.java`
- `recovery/normalized-src-vf/l1r/ao/CharacterGiftTable.java`

The claim path now:

1. validates the gift index, including the lower bound;
2. synchronizes on the per-character gift state;
3. rejects an already claimed slot;
4. clones the current claim byte array and sets the candidate bit only in the clone;
5. persists the candidate state first with a compare-and-set update:

```sql
UPDATE character_gift SET data=? WHERE objid=? AND data=?
```

6. requires `executeUpdate() == 1`;
7. returns fail-closed on SQL failure or CAS loss;
8. only after durable success publishes the new byte array to RAM and grants the reward.

No gift definition, reward semantics, packet index, or `character_gift` schema was changed.
