# BUG-850-256 — recurring reset task could stop permanently after exception

```text
LEVEL=L2
STATUS=PASS
PROMOTED=YES
```

## Problem

The daily timed-map/ranking reset and weekly quest reset scheduled their next execution only after the entire task body completed successfully. If any operation inside the task threw an exception, control jumped directly to the catch block and the next run was never scheduled, permanently stopping that recurring task until server restart.

## Fix

Move the next-run scheduling for both recurring jobs into `finally` blocks so recurrence is closed regardless of success or failure of the current run.

Only the scheduler recurrence closure was promoted. No unrelated weekly durable-delete change from the work branch was copied into the completed branch.
