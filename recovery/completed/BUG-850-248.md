# BUG-850-248 — Ranking backing-list top-50 bound

## Root cause

The old `RankingTable` top-50 path constructed a `subList` copy without assigning it back or mutating the stored backing list. Persistence only processed the first 50 entries, but the live backing lists themselves could remain larger than 50 and continue feeding later ranking responses/state.

## Fix

After ranking persistence, mutate each backing list in place until `size <= 50` by removing tail entries. This applies to the all-character list and every class bucket while preserving existing sort order.

Normalized and obfuscated authorities are kept equivalent:

- `recovery/normalized-src-vf/l1r/ao/RankingTable.java`
- `recovered-src-obf/ao/ba.java`
