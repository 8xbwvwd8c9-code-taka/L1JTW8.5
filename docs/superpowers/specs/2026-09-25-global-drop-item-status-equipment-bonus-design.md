# 全地圖掉落、指定道具狀態與裝備總加成設計

## 目標

在 850 核心上完成三個獨立模組：不受任何核心掉落倍率影響的全地圖掉落、由裝備中指定道具持有的能力狀態，以及依全身強化總值觸發的裝備總加成。能力型模組共用同一個可逆能力向量元件，但各自維持獨立的生命週期與 owner。

## 設計原則

- 850 核心、裝備生命週期、能力 API、封包與持久化行為是唯一權威。
- 381 資料只作為欄位與內容參考，不移植 381 runtime framework。
- 共用能力向量只描述與套用數值，不持有裝備或角色生命週期。
- 每個加成來源都有穩定 owner key，重複事件必須具備冪等性。
- 三個模組各有獨立總開關；無效規則隔離處理並留下明確日誌。

## 架構

### 共用能力向量

`StatModifier` 是指定道具狀態與裝備總加成共用的 850-owned 元件。它支援 STR、DEX、CON、INT、WIS、CHA、max HP、max MP、AC、MR、SP、HPR、MPR、近戰／遠距命中與傷害、物理／魔法減傷、屬性抗性及異常狀態抗性等經 850 核心證實可安全增減的欄位。

套用及移除必須使用同一份不可變能力快照，避免設定重載後使用新值反向扣除舊加成。max HP／MP 降低後，當前 HP／MP 必須限制在新的合法上限。尚未證實具有對稱增減 API 的欄位不得加入第一版 runtime。

建議資料表 `w_stat_modifier` 以 `modifier_id` 為主鍵，各能力欄位預設為 0，並具備 `enabled`。載入器拒絕無效數值，不讓單筆錯誤阻止其他有效規則載入。

### Owner 與差異更新

角色端維護目前已套用的 modifier owner 快照。owner key 至少包含模組與來源識別：

- 指定道具：`designated-item:<item-object-id>`
- 裝備門檻：`equipment-total:<rule-id>`

每次狀態變動先計算期望 owner 集合，再與目前集合做差異更新：只移除已失效 owner，只加入新 owner，保留未變更 owner。禁止以「全部扣除再全部重加」處理一般裝備事件。

## 全地圖掉落

### 資料表

建立獨立資料表 `w_global_drop`，不再使用 `w_map_designated_drop` 的特殊 map ID。

必要欄位：

- `id`：獨立主鍵。
- `item_id`：必填道具 ID。
- `chance`：整數百分比，預設 `1`，即 1%；填入 `100` 即 100%。
- `enabled`：預設 `1`。
- `note`：管理備註，預設空字串。

固定語義：每次成功固定建立 1 個、強化值 0 的道具。管理者只需填入 `item_id`；若未填 `chance` 即使用 1%。同一 item ID 可有多列，每列都是獨立掉落機會。

### 執行流程

850 核心完成怪物死亡資格判定並進入標準掉落流程時，全地圖掉落結算一次。每一筆啟用規則各自產生一次 `[1, 100]` 隨機值；隨機值小於等於 `chance` 時建立 1 個道具並放入該怪物的掉落持有者。

`chance` 合法範圍是 0 至 100。無效道具 ID 與超出範圍的機率在載入時停用該列並記錄日誌。

### 倍率隔離

此模組不讀取或套用任何核心物品掉落倍率、金幣倍率、地圖倍率、活動倍率、玩家掉寶加成或其他掉落修正。每列的 `chance` 是最終機率。是否具備掉落資格仍沿用 850 核心既有怪物死亡流程，避免召喚物、寵物或非標準死亡路徑重複觸發。

## 指定道具賦予狀態

### 資料表

建立 `w_item_designated_status`：

- `item_id`：指定道具 ID。
- `type`：互斥群組；同一角色同一時間每個 type 只能啟用一個道具。
- `modifier_id`：對應 `w_stat_modifier`。
- `enabled`：伺服器能力是否啟用。
- 變身、稱號、效果圖示及 skin 等客戶端相依欄位與各自驗證開關。

第一版可匯入經核對的 381 資料內容，但 runtime 只執行 850 核心已證實安全的伺服器能力欄位。變身、稱號、圖示、skin 及其他未驗證客戶端效果保留資料但不執行，並在載入或嘗試啟用時記錄原因。

### 生命週期

使用指定道具時切換該道具的裝備狀態。啟用前掃描角色實際持有且生效的指定道具；若同 type 已有另一件生效，拒絕切換且不改變任何能力。

道具實例是權威 owner。穿戴成功後才加入 modifier；卸除、刪除、交易或掉落前移除 modifier。登入完成後以背包中的實際裝備狀態重建 owner，不使用 `character_buff` 作為核心狀態來源。重複穿戴、重複卸除與重複登入還原不得造成重複加成或重複扣除。

若載入時發現同 type 有多件被標記生效，採確定性的單一勝出規則並記錄資料錯誤；其餘道具清除生效狀態，避免同群組多重加成。

## 裝備總加成

### 資料表

建立 `w_equipment_total_bonus`：

- `rule_id`：規則主鍵。
- `group_id`：同一套階級規則的群組。
- `metric`：`TOTAL_ENCHANT` 或 `OVER_SAFE_ENCHANT`。
- `stack_mode`：`HIGHEST` 或 `CUMULATIVE`。
- `threshold`：非負門檻值。
- `modifier_id`：對應 `w_stat_modifier`。
- `enabled`：規則是否啟用。

同一 `group_id` 必須使用一致的 `metric` 與 `stack_mode`；不一致時整組拒絕載入並記錄設定錯誤。

### 計算語義

- `TOTAL_ENCHANT`：加總所有符合 850 核心裝備資格之裝備的非負強化值。
- `OVER_SAFE_ENCHANT`：逐件計算 `max(0, enchantLevel - safeEnchantLevel)` 後加總。
- `HIGHEST`：每個 group 只套用已達門檻中 threshold 最高的規則。
- `CUMULATIVE`：每個 group 套用所有已達門檻的規則。

規則的裝備資格、安定值與強化值一律由 850 核心物件取得，不重建 381 裝備分類或安定值邏輯。

### 重算事件

穿戴、卸除、裝備強化變動、裝備刪除及登入裝備還原完成後觸發重算。重算產生期望 rule owner 集合，再使用共用差異更新機制同步。設定重載後，線上角色分批重算，避免在單一執行緒一次處理全部角色。

## 啟動、設定與失敗處理

三個模組使用獨立開關，預設關閉：

- `GlobalDropEnabled`
- `DesignatedItemStatusEnabled`
- `EquipmentTotalBonusEnabled`

資料表不存在時只停用對應模組並輸出一次明確錯誤，不阻止伺服器其他功能啟動。外鍵指向不存在的 modifier、無效 item ID、負 threshold、非法 enum 或機率越界均在載入階段隔離。執行期不得因單筆規則例外中斷怪物死亡或角色裝備流程。

## 測試設計

### 共用能力向量

- 每個支援欄位皆驗證套用後增加、移除後精確還原。
- 設定重載後仍使用原快照正確移除。
- 多 owner 疊加與任意順序移除保持正確。
- max HP／MP 降低後當前值不超過新上限。

### 全地圖掉落

- 只填 item ID 時機率預設為 1%，數量固定為 1。
- 自訂 `0`、`1` 與 `100` 分別代表 0%、1% 與 100%，邊界判定正確。
- 多列與重複 item ID 各自獨立擲骰。
- 改變核心掉落、金幣、地圖及活動倍率不改變本模組判定。
- 停用列、無效 item ID 與不具標準掉落資格的死亡流程不產生物品。

### 指定道具狀態

- 同 type 互斥，不同 type 可同時生效。
- 重複穿戴、卸除、刪除、交易、掉落及登入還原具冪等性。
- 非正常多件同 type 生效時只保留確定性的單一 owner。
- 未驗證的客戶端效果不送封包、不改角色狀態。

### 裝備總加成

- 總強化與總過安定採各自正確算法。
- HIGHEST 只套用最高達標階級；CUMULATIVE 套用所有達標階級。
- 強化下降、卸裝與刪除會移除已失效 owner。
- 多 group、臨界 threshold、0 強化與無裝備情況正確。

## 交付與驗收

交付內容包括：850 核心 Java 原始碼、安裝與回滾 SQL、設定範例、自動化測試或可重現驗證程式、驗證紀錄，以及三個 migration package 中同步的 `850匯入` 成果。不得以只有 SQL 或只有套件副本視為完成。

完成條件：新增測試先證明缺少功能而失敗，實作後相關測試及專案可執行的完整測試／編譯流程通過；任何既有失敗須逐項如實列出。三個功能在預設關閉狀態下不改變既有伺服器行為，啟用後符合本設計的 owner、倍率隔離與 850 核心優先原則。
