# 項目說明 — 怪物死亡召喚（Monster Death Spawn）

## 1. 基本資訊

| 欄位 | 值 |
|------|-----|
| **項目名稱** | 怪物死亡召喚 |
| **別名** | w_怪物死亡召喚 / Monster Death Spawn |
| **企劃來源** | `I:\天堂企劃.txt` 第 31 條：`L2,w_怪物死亡召喚,N/A` |
| **清冊 ID** | SQL（`w_怪物死亡召喚_202609221205.sql`）— 空檔 0 bytes |
| **module_id** | `怪物死亡召喚` |
| **企劃補充說明** | 低機率小怪 1% / BOSS 0.5%；死亡後在角色周邊復活並加強 1.5% 能力；復活後可再次觸發直到 100% 強化度；每次復活掉落率增加 1% |

## 2. 功能目的

怪物死亡時，依設定機率在玩家周邊召喚（復活）強化版本：

| 規則 | 值 |
|------|-----|
| 小怪觸發機率 | **1%** |
| BOSS 觸發機率 | **0.5%** |
| 復活強化能力 | **×1.5%**（每次強化累積） |
| 再觸發機制 | 復活後可再次死亡觸發，累積至 100% 強化度上限 |
| 掉落率加成 | 每次復活 **+1%** 掉落率加成 |
| 召喚位置 | 死亡角色周邊（tele_x/tele_y/tele_mapid） |

### 非目標

- 本項目不處理菁英化（另立項目）
- 掉落率加成不與菁英化系統加成混算（兩者獨立）

## 6. DB Schema 設計（初稿，待 schema 確認）

> ⚠️ 以下為依企劃需求的 850-first 設計草案，未使用 381 原始 schema。

```sql
-- 850匯入/db/install_monster_death_spawn.sql（草案，HOLD勿部署）
CREATE TABLE IF NOT EXISTS `w_monster_death_spawn` (
  `id` int(10) unsigned NOT NULL AUTO_INCREMENT,
  `dead_npc_id` int(10) unsigned NOT NULL COMMENT '死亡怪物NPC ID',
  `spawn_npc_id` int(10) unsigned NOT NULL COMMENT '召喚的NPC ID',
  `spawn_duration_min` int(5) unsigned NOT NULL DEFAULT 10 COMMENT '召喚持續時間(分鐘)',
  `death_talk` varchar(255) NOT NULL DEFAULT '' COMMENT '死亡廣播文字',
  `tele_x` int(10) NOT NULL DEFAULT 0 COMMENT '傳送目標X',
  `tele_y` int(10) NOT NULL DEFAULT 0 COMMENT '傳送目標Y',
  `tele_mapid` int(5) NOT NULL DEFAULT -1 COMMENT '傳送地圖ID，-1=不傳送',
  `is_boss` tinyint(1) NOT NULL DEFAULT 0 COMMENT '0=小怪 1=BOSS（機率不同）',
  `trigger_chance_pct_x10` int(4) NOT NULL DEFAULT 10
    COMMENT '觸發機率×10（10=1.0%, 5=0.5%），×10避免浮點',
  `strength_pct` int(5) NOT NULL DEFAULT 150
    COMMENT '每次復活能力強化(%)，150=×1.5%',
  `max_strength_pct` int(5) NOT NULL DEFAULT 10000
    COMMENT '最大累積強化度(%)，10000=100%上限',
  `drop_bonus_pct_per_spawn` int(3) NOT NULL DEFAULT 1
    COMMENT '每次復活掉落率加成(%)，1=+1%',
  `note` varchar(255) NOT NULL DEFAULT '',
  PRIMARY KEY (`id`),
  KEY `idx_dead_npc` (`dead_npc_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='怪物死亡召喚規則（850-first設計）';
```
