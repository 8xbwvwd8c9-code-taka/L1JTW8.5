# 自動狩獵系統：850 原生重構式移植規格

## 1. 目標

以 850 服務端既有的角色、地圖、移動、戰鬥、技能與執行緒介面為基礎，重構並導入可受控的玩家自動狩獵系統。880 僅作為需求與行為證據來源，不直接覆蓋 850 核心類別，也不照搬已知缺陷。

本項目完成後，玩家可透過受權道具開啟設定介面，在允許的地圖與時段內啟動自動尋怪、移動、普通攻擊及經設定的攻擊技能；任何停止條件成立時，系統必須安全停止並清除執行狀態。

## 2. 已確認現況

### 2.1 880 來源能力

880 服務端已確認包含下列能力：

- `PcAI` 玩家 AI 執行迴圈。
- `L1PcInstance.startAI()` 及尋怪、目標、移動、攻擊與技能邏輯。
- `L1ActionPc` 中的 `ksgj` 啟停指令及掛機設定指令。
- `Hang_fu` 掛機符入口與 `guajiqd` 設定畫面。
- `L1EquipmentTimer` 掛機符剩餘時間與到期停止控制。
- `mapids.autobot` 地圖掛機權限。
- 掛機範圍、禮貌模式、無目標瞬移、遇 BOSS 瞬移及技能條件。

### 2.2 850 缺口

850 目前沒有下列項目：

- 玩家專用自動狩獵 AI 執行器。
- 玩家自動狩獵啟動、停止及狀態生命週期。
- `guajiqd` 對應的服務端控制流程。
- `Hang_fu` 掛機符執行類別與時間授權流程。
- `mapids.autobot` 欄位及地圖模型傳遞鏈。
- 自動狩獵技能、範圍、瞬移與禮貌模式設定。

### 2.3 客戶端事實

以下兩個檔案大小相同且 SHA-256 相同：

- `I:\L880C\天堂客戶端880C\Contents\china_autohelper_server-common.bin`
- `I:\8.50c客服端\Contents\china_autohelper_server-common.bin`

因此本規格不把該檔案列為需要匯入的客戶端素材。只有在封包或畫面驗證證明 850 缺少其他素材時，才能將該素材加入 `850匯入/客戶端/`，並記錄來源、用途與雜湊。

## 3. 選定方案

採用「850 原生重構式移植」。

不採用以下方案：

- 整段覆蓋 850 `L1PcInstance`：會把版本差異、無關功能及 880 缺陷一起帶入。
- 直接複製 880 全部掛機類別後再修編譯：類別依賴與服務端生命週期不符合 850，無法證明執行安全。
- 僅加入客戶端素材：目前證據顯示真正缺口在服務端與 DB，不能形成可運作功能。

## 4. 套件交付結構

正式交付資料位於：

`migration/381-to-850/packages/自動狩獵系統/`

結構固定如下：

```text
自動狩獵系統/
├─ 880來源證據/
│  ├─ 核心/
│  ├─ DB/
│  └─ 客戶端/
├─ 850匯入/
│  ├─ 核心/
│  ├─ DB/
│  └─ 客戶端/
├─ 驗證/
├─ 項目說明.md
└─ manifest.json
```

`850匯入/核心/` 只放本項目實際需要的 Java 或編譯後 class，不放完整服務端、不放無關相依類別。所有修改既有核心類別的內容，均需保存可追溯的完整目標檔，並在 `manifest.json` 記錄目標路徑。

## 5. 核心架構

### 5.1 自動狩獵控制器

建立玩家專用控制器，負責：

- 原子化啟動與停止，禁止同一角色建立兩個 AI 工作。
- 保存執行狀態、起始座標、搜尋範圍與目前目標。
- 將每一輪工作拆成：驗證狀態、檢查目標、搜尋目標、移動或攻擊。
- 使用 850 原生執行緒池排程，不自行建立永久裸執行緒。
- 在例外、登出、死亡或權限失效時執行同一套清理流程。

### 5.2 角色整合邊界

850 玩家類別只新增必要的狀態與委派介面：

- 啟動自動狩獵。
- 停止自動狩獵並提供停止原因。
- 查詢是否正在執行。
- 取得或更新本項目的玩家設定。

尋怪、路徑、攻擊與技能執行優先呼叫 850 現有服務，不把 880 的整段 `L1PcInstance` 邏輯直接貼入。

### 5.3 設定與控制入口

掛機符開啟 `guajiqd` 設定頁，服務端處理下列操作：

- 開始／停止。
- 開怪技能。
- 攻擊技能。
- 技能間隔。
- 最低 MP 條件。
- 定點狩獵範圍。
- 禮貌模式。
- 無目標瞬移。
- 遇 BOSS 瞬移。

所有客戶端傳入的技能編號與數值都必須由服務端驗證，不能直接信任 HTML action 參數。

## 6. 狀態與資料流

啟動流程：

1. 玩家使用有效掛機符開啟設定頁。
2. 玩家送出開始指令。
3. 服務端驗證角色狀態、武器、地圖、時段、掛機符剩餘時間及是否已有工作。
4. 驗證通過後建立單一控制器工作並標記為執行中。
5. 每輪先驗證停止條件，再搜尋或更新目標，最後執行移動、普通攻擊或技能。

停止流程必須收斂到單一方法，清除目標、路徑、執行旗標及控制器參照。停止後不得保留可繼續攻擊或移動的排程工作。

## 7. 強制停止條件

以下任一條件成立即停止：

- 玩家登出或連線狀態失效。
- 玩家死亡或 HP 小於等於零。
- 玩家進入睡眠、麻痺或禁止操作狀態。
- 地圖不允許自動狩獵。
- 進入城戰區、主城安全限制區或其他明確禁止區域。
- 掛機符不存在、未啟用或剩餘時間歸零。
- 到達禁止使用時段。
- 系統收到人工停止命令。
- 控制器工作發生未處理例外。

停止原因需寫入服務端日誌；正常停止使用資訊層級，例外停止保留堆疊資訊。

## 8. DB 設計

### 8.1 地圖權限

在 850 `mapids` 新增布林型 `autobot` 欄位，預設值為禁止。地圖資料載入器、地圖資料模型與執行中地圖物件必須完整傳遞此值。

預設禁止是必要安全邊界；只有明確列入遷移 SQL 的地圖才能設為允許。

### 8.2 掛機符與時間授權

掛機符需具備：

- 明確道具編號、名稱及執行類別。
- 可查詢的剩餘使用時間。
- 只在自動狩獵執行期間扣除時間。
- 到期時只觸發一次停止與到期通知。
- 重新登入後不得自動恢復上一個執行工作。

880 的道具編號只能在確認未與 850 現有資料衝突後採用。

### 8.3 玩家設定保存

第一版只保存必要且可驗證的使用者設定；執行中狀態不寫入 DB。服務端重啟或玩家重登後保持停止狀態。

## 9. 時段控制

`BotStartHour` 與 `BotEndHour` 必須由 850 設定載入器實際讀取並在啟動及執行期間驗證。

時段規則採半開區間，起始小時包含、結束小時不包含；跨午夜區間必須有獨立測試。若設定值不在 0 至 23，服務端啟動時回報設定錯誤並停用自動狩獵，不使用猜測值。

## 10. 880 已知缺陷及禁止照搬項目

- 880 技能 HP 消耗分支把 HP 計算結果寫入 MP；850 實作必須分別更新 HP 與 MP，並以測試鎖定。
- `BotStartHour`、`BotEndHour` 在 880 來源中未找到 Java 載入或引用；850 必須實際接線。
- 880 AI 在大型玩家類別中高度耦合；850 必須以控制器委派方式限制修改面。
- 880 使用多個布林旗標控制生命週期；850 必須防止重複啟動及停止競態。
- 880 部分停止路徑直接傳送角色；850 不把傳送視為通用清理動作，只有規格明定的地圖或瞬移功能才能傳送。

## 11. 錯誤處理與安全限制

- 找不到目標不是錯誤；依設定原地巡弋或執行受控瞬移。
- 找不到路徑時清除該目標，避免無限追逐。
- 技能不存在、未學習、MP 不足、冷卻中或目前狀態禁止施法時，不執行該技能。
- 自動狩獵不得繞過原有攻速、移速、技能冷卻、地圖及 PK 限制。
- 禮貌模式不得選取已被其他玩家有效攻擊的怪物。
- 自動狩獵只鎖定服務端判定為合法的怪物目標。
- 所有數值設定需限制上下界，避免負範圍、零延遲或整數溢位。

## 12. 測試與驗收標準

### 12.1 單元與元件測試

- 同一玩家連續兩次啟動只產生一個工作。
- 所有強制停止條件會清除執行狀態與目標。
- `autobot=0` 的地圖拒絕啟動，執行中進入該地圖立即停止。
- 普通時段與跨午夜時段判定正確。
- 技能 HP 消耗只扣 HP，MP 消耗只扣 MP。
- 未學技能、MP 不足與非法技能編號不會施法。
- 掛機符只在執行期間扣時，到期只停止一次。
- 找不到路徑會放棄目標，不形成無限工作。

### 12.2 整合驗證

- 掛機符可開啟設定頁，所有 action 均由服務端驗證。
- 允許地圖可完成尋怪、移動、攻擊及重新選取目標。
- 登出、死亡、傳送、道具到期及人工停止後不再移動或攻擊。
- 停服流程不殘留自動狩獵工作。
- DB 遷移可重複檢查，且不覆蓋 850 已存在的道具編號。
- 850 服務端完整編譯通過。

### 12.3 客戶端驗證

- 850 現有客戶端可顯示設定介面並送出所有控制 action。
- 若缺少 `guajiqd` 畫面或文字資源，先取得實際缺失證據，再從 880 抽取單一必要素材。
- 不重複放置已證明完全相同的 `china_autohelper_server-common.bin`。

## 13. 完成條件

本項目只有在以下條件全部成立時才能標記完成：

- `880來源證據`、`850匯入`、`驗證`、`manifest.json` 與本文件齊全。
- 每個核心檔案、SQL 與客戶端素材均可追溯來源與目的地。
- 850 完整編譯成功。
- 自動化測試與人工整合驗證結果寫入 `驗證/`。
- 已知缺陷皆有測試或明確的驗證紀錄。
- 首頁補上問題、原因、解決方法、驗證結果與獨立項目連結。
- 最終修改放入使用者指定的 BUG 修補完成支線。
