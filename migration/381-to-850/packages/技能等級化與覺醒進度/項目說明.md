## 2. 核心業務流程與權威架構

### 2.1 吃書學習與自動升階流程
1. **未學習技能**：
   - 玩家背包持有對應技能書。
   - 第一次使用/吃技能書 -> 於 `character_skills` 建立權威紀錄，學會 **LV1**，並於 `character_skill_progress` 初始化 `stage = 1`, `duplicate_book_count = 0`。
2. **已學會技能（重複吃書）**：
   - 不重複在 `character_skills` 寫入重複 skill，改為累積 `character_skill_progress.duplicate_book_count`。
   - 每累積滿 **5 本** 同技能書，自動升到下一階：
     - **LV1 吃滿 5 本** -> 自動升級為 **LV2**（`stage = 2`, `duplicate_book_count` 歸零或重算）。
     - **LV2 再吃滿 5 本** -> 自動升級為 **LV3**（`stage = 3`, `duplicate_book_count` 歸零）。
   - **升到 LV3 後不再吃書自動往上升**。
3. **技能覺醒（NPC 交互）**：
   - 技能達到 LV3 後，玩家尋找「技能覺醒 NPC」。
   - NPC 驗證：
     1. 該技能在 `character_skill_progress` 處於 `stage = 3` 且 `awakening = 'NONE'`。
     2. 背包具備規則表指定之足量材料／道具。
   - 玩家二選一：選擇 **A 路線** 或 **B 路線** 覺醒。
   - **A/B 永久互斥**：一旦選定 A（或 B），DB 標記 `awakening = 'A'`（或 `'B'`），不可同時擁有，不可重複覺醒另一側。

## 3. DB Schema 與交易安全設計

### 3.1 DB Engine 混用策略
- 舊 381 / 850 原生表格（如 `character_skills`、`skills` 等）保持既有 MyISAM，不必強制全域轉換以免破壞原有架構。
- 新增之進度與規則表格（`character_skill_progress`、`skill_upgrade_chain`）採用 **InnoDB**，以支援事務與行鎖。
- **跨 Engine 交易補償機制**：
  - 由於 MyISAM 不支援交易 rollback，吃書、扣除道具、修改技能等跨表操作必須設計為 **嚴格防禦性作業**：
    1. 驗證前置條件（玩家持有物品數量、當前 stage、重複數）。
    2. 採用 idempotent 操作（以 `char_id + skill_chain_id` 為 UNIQUE KEY）。
    3. 扣除道具與更新技能需有明確先後順序，並具備日誌／補償（compensation）記錄，嚴格避免「書扣了但技能沒升」或重複升級。

### 3.2 表結構定義

#### (A) 規則表：`skill_upgrade_chain` (InnoDB)
定義技能樹鏈、各階所需書本數、覺醒分支與所需材料：
```sql
CREATE TABLE IF NOT EXISTS `skill_upgrade_chain` (
  `skill_chain_id` int(10) unsigned NOT NULL AUTO_INCREMENT COMMENT '技能鏈主鍵ID',
  `chain_name` varchar(64) NOT NULL DEFAULT '' COMMENT '技能鏈名稱',
  `book_item_id` int(10) unsigned NOT NULL COMMENT '對應技能書道具ID',
  `skill_id_lv1` int(10) unsigned NOT NULL COMMENT 'LV1技能ID',
  `skill_id_lv2` int(10) unsigned NOT NULL COMMENT 'LV2技能ID',
  `skill_id_lv3` int(10) unsigned NOT NULL COMMENT 'LV3技能ID',
  `upgrade_cost_books` int(5) unsigned NOT NULL DEFAULT 5 COMMENT '每階升級所需技能書數量(預設5)',
  `awakening_a_skill_id` int(10) unsigned NOT NULL DEFAULT 0 COMMENT '覺醒A技能ID',
  `awakening_a_materials` varchar(255) NOT NULL DEFAULT '' COMMENT '覺醒A所需材料(item:count,...)',
  `awakening_b_skill_id` int(10) unsigned NOT NULL DEFAULT 0 COMMENT '覺醒B技能ID',
  `awakening_b_materials` varchar(255) NOT NULL DEFAULT '' COMMENT '覺醒B所需材料(item:count,...)',
  PRIMARY KEY (`skill_chain_id`),
  UNIQUE KEY `uk_book_item` (`book_item_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='技能階級鏈與覺醒規則表';
```

#### (B) 進度表：`character_skill_progress` (InnoDB)
追蹤玩家各技能的階級進度、書本堆疊與覺醒狀態：
```sql
CREATE TABLE IF NOT EXISTS `character_skill_progress` (
  `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
  `char_id` int(10) unsigned NOT NULL COMMENT '角色ID',
  `skill_chain_id` int(10) unsigned NOT NULL COMMENT '對應skill_upgrade_chain主鍵',
  `current_skill_id` int(10) unsigned NOT NULL COMMENT '目前生效的技能ID',
  `stage` tinyint(2) unsigned NOT NULL DEFAULT 1 COMMENT '當前階級: 1=LV1, 2=LV2, 3=LV3',
  `duplicate_book_count` int(5) unsigned NOT NULL DEFAULT 0 COMMENT '累積同技能書本數(0~4)',
  `awakening` enum('NONE','A','B') NOT NULL DEFAULT 'NONE' COMMENT '覺醒狀態: 永久互斥',
  `update_time` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_char_chain` (`char_id`, `skill_chain_id`),
  KEY `idx_char_id` (`char_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8 COMMENT='角色技能等級與覺醒進度表';
```

#### (C) 既有角色技能表：`character_skills`
- 繼續作為「角色目前擁有的技能」唯一 Authority。
- 當 stage 升級（LV1 -> LV2）或完成覺醒（LV3 -> A/B）時，由核心負責將舊 skill_id 移除或替換為新 skill_id，維持 packet 與客戶端顯示一致。

## 4. 850 原生核心對照與缺口

| 項目 | 850 原生狀態 | 本模組需求 | 解決方案 |
|------|-------------|-----------|---------|
| 學習技能進入點 | `UseItem` / 技能書使用呼叫 `L1SkillUse` 或直接寫入 `character_skills` | 攔截重複吃書行為，改走累積升級 | 建立 `SkillProgressHandler` 統一控制 |
| 技能進度儲存 | 無進度表，僅有學會/未學會二元狀態 | 需記錄 stage、重複書數、覺醒互斥分支 | 新增 `character_skill_progress` (InnoDB) |
| 升級與覺醒規則 | 無鏈式對照 | 需對照 1/2/3 階技能與 A/B 分支 | 新增 `skill_upgrade_chain` 規則表 |
| 覺醒 NPC 交互 | 無 | NPC Action 判斷 LV3 + 扣材料 + 二選一互斥覺醒 | 撰寫專用 NPC Action 腳本或 Java Handler |
